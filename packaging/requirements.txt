# The exact dependency set the daemon's virtualenv is built from.
#
# postinst runs pip as root, at install time, with network access. Without this
# file that install was `pip install --upgrade faster-whisper numpy evdev`,
# which resolves to whatever is newest on PyPI at the moment someone happens to
# install — so the code running as root differed between two installs of the
# same .deb, and a compromised or simply broken release upstream would land
# straight in /opt/baatsun. Pinning is what makes the install reproducible and
# reviewable.
#
# This is the full closure, not just the three direct dependencies: an
# unpinned transitive dependency is the same exposure one level down.
#
# To regenerate after bumping anything, and to check the result is closed:
#     python3 -m venv /tmp/baatsun-venv
#     /tmp/baatsun-venv/bin/pip install faster-whisper numpy evdev
#     /tmp/baatsun-venv/bin/pip freeze --exclude pip
#     # then confirm nothing unpinned sneaks in:
#     /tmp/baatsun-venv/bin/pip install --dry-run -r packaging/requirements.txt
#
# Do not exclude setuptools when regenerating. It is a real runtime requirement
# of ctranslate2, so a venv that already has one hides it from `pip freeze` —
# which is exactly how it ends up as the one unpinned package in an otherwise
# pinned install.
#
# Pins are exact, so a Python version with no wheel for one of them fails the
# install loudly rather than quietly resolving to something else. numpy 2.5.1
# needs Python 3.12+, which is why the .deb Depends on python3 (>= 3.12) rather
# than the 3.10 the daemon itself would run on. If a newer distro has no wheel,
# regenerate rather than loosening.
#
# evdev publishes no Linux wheels — postinst compiles it, which is why the
# package Depends on python3-dev. A laptop without headers fails at
# `#include <Python.h>` and leaves the .deb half-configured.
